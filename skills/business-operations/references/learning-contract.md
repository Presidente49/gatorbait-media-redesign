# Learning without mixing businesses

Maintain knowledge at three distinct levels; use existing version control and work-item records, not a new memory server.

## Upstream library

Keep upstream files and MIT notices unchanged at the pinned commit. A local skill references them instead of silently rewriting them. An update proposal compares old/new versions, licensing, relevant security/maintenance changes and affected tests. Never auto-follow a moving branch or install new dependencies as part of an update. Return corrections upstream only when separately authorized and free of client information.

## Portable method

General rules belong in this skill only when evidence is repeated, measured, or clearly structural AND a reviewer accepts the stated scope. Record the source references, independent incident count, hypothesis, conditions, metric definition, counterexamples, limits, review reference and affected regression test. For cross-business generalization, verify transfer to another context or supply a structural rationale; otherwise retain a project-scoped candidate.

Promotion is an explicit versioned patch with a regression test, not a sentence appended automatically after each run. Outcome labels are RETAIN, REJECT, INCONCLUSIVE and VERIFIED_RECOVERY. A reviewed policy decision is labeled OWNER_DIRECTION, not presented as a measured causal finding. An observation without a credible denominator/baseline does not prove lift.

## Business-specific adapter and evidence

Brand, editorial hierarchy, platform IDs, consent rules, approved prices, contacts, account permissions and current metrics stay in the selected business. Sensitive evidence remains in its authorized provider/private store; a public issue receives only sanitized references and aggregate evidence that is safe to disclose. Never export customer lists, credentials, personal addresses or client-specific performance into the portable skill.

## Required change record

- Original work-item ID, evidence timestamp/coverage and exact artifact/version.
- Expected versus observed result; prior related outcomes and independent incidents.
- Outcome and scope: upstream reference, portable method, project adapter, or volatile state.
- Proposed change, success measure, counterexample/negative test and review owner.
- Review acknowledgment, accepted version, verification and rollback.

If later evidence contradicts a promoted rule, mark it RETIRED or narrow its scope in a reviewed patch. Preserve its history. Do not accumulate conflicting exceptions forever.

## What this does not mean

Saving skills improves the instructions available to future sessions; it does not retrain model weights, guarantee every chat loads the skill, create cross-agent memory automatically or give a model permission to write production. Actual discovery and execution must be checked on each intended host.
