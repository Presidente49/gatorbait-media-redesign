# GatorBait Publication QC

Use under [Master Control](../master-control/SKILL.md) when checking a posted story, front-page photo, crop, visible byline, duplicated artwork or a presentation release. Read [START-HERE](../../docs/START-HERE.md), the current provider object and the smallest relevant [publishing gate](../../docs/GATORBAIT-PUBLISHING-EMAIL-PLAYBOOK.md#1b-feed-and-spaces-cover-gate). Current owner instructions supersede dated examples.

This is a read-only verification role. Return evidence and the smallest responsible correction to the designated production writer. Do not publish, patch, upload, send, change permissions or create a watcher. Symphony is retired from this workflow by owner direction; use available direct provider tools and authorized browser access.

## Inputs

- Exact canonical story URL and native post ID, intended writer and source revision.
- Intended permanent cover/hero media ID, credit, alt text and approved artwork provenance.
- Claimed change, current native revision or immutable deployed source, and rollback reference.
- Current front-page order and supporting-story direction from the rulebook or active request.

Resolve missing current identities with read-only discovery. Never reuse remembered revisions, post IDs, dates or commit pins as present-tense facts.

## Inspect the public front page first

1. Open the ordinary public homepage before proposing a fix. Record its actual lead, story links, titles, visible authors and image assets. Inspect every current card, normally nine eligible stories, at phone and desktop widths.
2. Require a visible `By [verified writer]` on the lead and each card, separately from photographer/artwork credits. Compare to the native writer/RSS creator. Do not infer authorship from a photograph or assign a named writer by style.
3. Compare normalized Wix media IDs across all visible front-page stories. Require distinct relevant images, including cards below the initial viewport. A different crop or rendition of one media ID is still a repeated photo. Count expected photo boxes even if their image is pending, hidden or missing; scroll lazy cards and confirm decoding.
4. Keep every title, author, image, alt and destination attached to the same story. Do not borrow the next article's image as a fallback or apply the current article's headline as alt text to unrelated recommendations. If a story has no verified image, report it honestly.
5. Preserve the current editorial order without changing publication dates. Rays/secondary baseball stays compact supporting coverage under the current owner direction, even if another feature is absent. The broader landing-page redesign remains a separate deferred discussion.

## Verify media and the complete article

- Read the native saved custom cover, matching hero, `media.displayed: true`, original dimensions and media-manager `READY` status. Temporary links and a body photograph do not establish a native feed cover.
- Require one intended visible website lead, with no duplicate opening body artwork. Inspect the actual rendered page; saved native fields, RSS, OG tags, a CSS class or a node count alone do not prove the image is visible.
- Preserve the entire manuscript and full ending, actual writer, canonical URL and original publication identity. Check readable paragraphs, heading hierarchy, appropriate opening initial on prose, captions, credit links and accessible controls. A photo credit or quoted deck must not receive the prose initial.
- Check ordinary public pages at 390, 430 and 1366 pixels. Add 320 or wider desktop coverage when the affected layout needs it. Record which widths actually ran, image decoding, overflow, console/network failures and screenshots. Browser emulation is not physical-device or Safari proof.
- Keep real photographs proportional. Inspect faces, action and focal points in widescreen cards; never stretch dimensions independently. Show text-bearing artwork whole with an appropriate contain treatment. Inspect both phone and desktop crops rather than approving a source image alone.
- Use honest credits: identify archival photographs as archival and illustrations/AI-assisted artwork as such where applicable. Do not present a generated scene as a game photograph.
- Inspect the actual Spaces list/card and destination separately when that surface is in scope. Native media, website rendering, Spaces card appearance, push-action completion and a device receiving a notification are distinct states. Unavailable evidence remains unverified.

## Artwork source and supplied masters

All final GatorBait artwork originates in **regular ChatGPT Pro, normal Chat mode**. Follow [Graphic Design](../gatorbait-graphic-design/SKILL.md) and [Broadcast Graphics](../gatorbait-broadcast-graphics/SKILL.md). Technical workers may research, brief, prepare authentic approved assets, QA and mechanically export/optimize/integrate the approved master; they do not supply replacement creative.

Keep the conversation link, prompt/reference inputs, downloaded original master and derivative provenance. When the owner says to upload an original unchanged, verify the uploaded original's bytes or hash against the attachment. Do not silently substitute an adaptation. A creative variation returns to regular ChatGPT Pro.

## Verify one repair without replaying distribution

The production writer must fresh-read the responsible entity, preserve settings and rollback, and guard its current revision plus exact HTML/source fingerprint before one minimal change. A mismatch is an abort, not permission to skip the guard. QA then checks native/provider results and the independent ordinary public page.

Native save and public cache propagation are separate. Inspect which actual source the public page loaded; allow one bounded confirmation after a stale response. Do not repeatedly patch to chase caching, add another loader, republish a story or replay email/push/social to diagnose presentation.

For externally served code, verify the immutable URL returns JavaScript with the expected exact bytes/hash and content type, then verify the browser actually loads it under the site's policy. A new CDN reference can fail even when an older cached reference works. Treat a repository package-size rejection as a delivery constraint; use an approved immutable delivery route after validation rather than retrying the same rejected reference. Keep volatile CDN URLs and commit pins in dated release receipts, not this skill.

## Output contract

Return a compact receipt with:

- Checked time, canonical URL/native identity and expected versus observed state.
- Per-surface results: provider save, homepage, article, Spaces card and device delivery, using `PASS`, `FAIL` or `UNVERIFIED` with evidence.
- Checked widths, actual visible byline, intended/observed media IDs, duplicate count, full-ending check, crop/credit result and screenshot references.
- Smallest responsible fix, its owner and exact unresolved blocker. Separate source defects, missing media, template defects and related-story content without mislabeling one as another.
- Whether any production change occurred, current release/rollback reference and any propagation limit.

Never report "fixed" from a model's recommendation, a prepared file, an API success or agreement between workers. The observed reader/provider outcome closes the check.
