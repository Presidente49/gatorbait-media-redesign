# Record Symphony execution and promote verified lessons

Use when the owner asks to watch a Symphony repair batch, preserve its actions, or turn demonstrated outcomes into a reusable skill. Master Control remains the controller contract; the recorder observes and documents rather than dispatching repairs or becoming another production writer.

## Establish the watch

- Reuse the current campaign conversation, task registry and evidence artifacts. Find an existing matching recorder before creating another.
- Record the owner's scope, authorized duration, actual stop time, source conversation and skill branch. If ongoing follow-up is requested, use the host's supported thread heartbeat/automation and read back its saved state. A promise to check later is not a running monitor.
- Use a bounded interval appropriate to the work. Native agents can append receipts as actions happen; the external recorder collects the deltas. Do not repeatedly ask for an unchanged full report.
- Keep a real deadline in both the schedule and prompt. Before each run, check the deadline and whether the assigned batch is already terminal. Finalize the evidence and pause only this recorder when its work ends. Do not extend the window or create repair schedules from a request to observe.
- Current owner instructions may authorize a new parallel batch or recorder after an earlier no-more-runs instruction. Apply the new instruction to its scope; do not retain a superseded precaution as a permanent prohibition.
- A saved profile, trial note, roster or old credit counter is not current billing evidence. Record the source and observation time; do not infer charges or remaining free actions from contradictory snapshots. Use only the authorized allowance and never buy or upgrade merely to keep agents busy.

## Capture observable actions

Use native task/tool records where available. A worker's narrative is a reported claim until its evidence has been read. Capture tool actions and outcomes; private reasoning is not required.

A compact event record can contain:

```json
{
  "event_key": "stable native event ID or task/resource/operation/time key",
  "observed_at": "UTC timestamp",
  "task_id": "actual native task",
  "agent": "responsible worker",
  "resource_id": "specific changed or inspected object",
  "operation": "read, prepare, apply, verify, rollback or block",
  "tool": "actual tool and method",
  "result": "code and non-secret result",
  "change": "protected-field diff or snapshot hashes",
  "verification": "read-back, public/runtime check and its limits",
  "rollback": "private original snapshot or versioned source reference",
  "artifact": "existing evidence path",
  "evidence_level": "reported, provider-read or independently-verified"
}
```

Append deduplicated deltas to the existing evidence and retain a cursor. Preserve failed attempts and corrections rather than replacing them with a success summary. When a native log is missing or truncated, record the missing range and request only that range.

Never copy credentials, cookies, authorization headers, private message bodies or customer records into a skill, public issue or shareable log. Keep operational evidence private; public coordination contains only the non-sensitive result needed by the next owner.

Keep separate:
- task status, approval-card status and actual resource state;
- source commit, deployed pin, current object revision and public rendering;
- prepared payload, successful write, read-back and delivered customer outcome;
- observed capability and a route merely described in documentation.

## Collect without duplicating work

Use one coordinating conversation. Collect an outstanding `working` response with its returned conversation ID rather than resending the same request. New owner steering is a scoped update, not permission to duplicate the original job.

Give parallel workers distinct files or resources, one deliverable and a check that can disprove the diagnosis. Record admitted, running and queued tasks from current registry evidence. An accepted brief or a roster is not proof of execution.

One designated writer serializes production changes after current claims, snapshots, review and rollback are checked. The recorder may request receipts and independently read results; it does not retry production writes to make a task card look complete.

An appended task note is not acknowledged delivery. If a worker's final artifact does not cite or apply it, retain that limit instead of reporting a confirmed handoff.

## Promote into the existing skill

- Promote only a reusable decision or mechanism supported by a real tool result, read-back or runtime check. Capture the smallest lesson that changes the next operator's action.
- Keep changing task IDs, active revisions, credit balances, deadlines, contact counts and unresolved diagnoses in dated evidence. Do not make them permanent doctrine.
- Update the existing Symphony Pit Crew or operating adapter rather than creating another controller or copied manual. Link a focused reference when a conditional procedure would bloat the entrypoint.
- Work on an isolated branch; preserve dirty canonical files and other workers' edits. Validate skill frontmatter, reference paths, scope and the actual diff, then commit only the assigned documentation. Reuse an existing review PR for later learning updates.
- A narrow docs update does not authorize applying the repair it describes. Runtime changes retain their own review and verification.
- At the end, report actual verified fixes, remaining limits, saved evidence and the resulting skill commit or PR. A monitor being active is not completion of its watched work.

## Demonstrated interpretation checks

- A coordinator unable to read the coordination registry can echo an earlier held state from the recorder's question. That is caller context, not an independent read. Retrieve the current claim/receipt, then compare the native revision, payload hash and ordinary public source. Preserve earlier task-lab limits and missing per-call logs even when a later release is independently verified.
- A normal native write can succeed while an old `ACTION_NEEDED` card remains open. Verify the changed resource and preserve the tool receipt; do not reapply the write or impersonate the owner to close the card.
- A previous agent-authored claim that writes require the owner's native chat is not a universal rule. Distinguish the original machine refusal from an interpretation, and use the ordinary authorized route when it permits the action. Respect actual denials.
- A supported GET can verify a stored email body and target URL without proving rendered variables, a preview or delivery. Report each separately.
- A correct Custom Embed readback can precede public propagation. Compare the stored revision and exact loader spans, then verify ordinary canonical navigation independently; an initially cached old loader alone is not a reason to repeat the write or publish unrelated Editor changes. Do not infer a general propagation deadline from one observation.
- Match a photo credit to the exact media identity and its caption or alt text. A different image elsewhere on the same article can carry another photographer's credit. Verify the rendered links too: a source URL in issue JSON can be filtered out by the renderer's existing URL policy.
- Item-level SEO title and description overrides do not establish Open Graph or Twitter metadata. Read own and resolved tags, then independently inspect each public head field; preserve inherited canonical URLs, images and unrelated tags when correcting the intended fields.
- An unsupported app-page Item SEO route does not establish that its SEO is unwritable. Check the official page-type SEO Patterns API and offered variables. A pattern affects the whole page type, replaces its complete tag list and has no revision: use suitable generic copy, preserve default templates, snapshot and re-read immediately, then verify ordinary public title/canonical/image and description fields. A stored pattern alone does not prove the intended route resolves it.
- A deliberately dated magazine edition can disagree with a current-story freshness assertion. Compare the edition policy and content contract before replacing the edition or weakening the test. An old pin is not source drift if the deployed file bytes equal current source.
- When the owner asks for today's coverage, an archive label does not fulfill that outcome. Establish the current date and upcoming matchup from fresh primary sources, build a current topical issue, preserve older assets separately, and withdraw any superseded deployment candidate before continuing. A generic feed must not replace a topical lead with a newer unrelated story.
- A curated subset of category chips is not a broken taxonomy merely because the native category count is larger. Check identities and actual routes; label source mapping and browser click-through separately.
- Desktop-UA viewport resizing can invoke Wix's desktop layout at phone widths. Use an appropriate mobile UA, touch and device metrics before recording a phone-layout defect. Without a visible consent panel, a run cannot clear a first-visit consent-overlap finding.
- Diagnose layout against the live DOM and computed styles to find the owning embed; another skin can outrank the formatter. Use stable hooks and a route guard when evidence covers one article. Measure both the hero section and image, preserve the whole photo with containment, and verify an unaffected control article. A banner-absent geometry preview still needs production consent QA before clearing the finding.
