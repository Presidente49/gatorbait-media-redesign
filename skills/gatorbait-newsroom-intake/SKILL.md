# GatorBait Newsroom Intake

Use under [Master Control](../master-control/SKILL.md). Read the current rulebook, private pending queue and [intake contract](../../docs/loops/newsroom-intake-contract.md); current owner instructions control scope. **Symphony is retired from this workflow by owner direction, Oct. 29, 2026. Do not dispatch to it, retry it, or propose a paid fallback.**

## Inputs and authority

- Requested writer(s), source surface, time window and intended next stage. Infer routine choices from current records; do not ask the owner to restate known context.
- Current provider access, writer identity and private source-to-story ledger. A remembered account, folder name or post title is a search lead, not verified access.
- Intake workers read sources and prepare local/private artifacts. The designated controller alone performs authorized Wix production changes. This skill does not create a scheduler, account connection, email acknowledgment or competing publisher.

## 1. Verify the source surface

1. Use the relevant direct provider connector. Verify the actual Gmail profile before treating a query as business-newsroom coverage. A personal inbox's empty search says nothing about an inaccessible business inbox. Record the precise account mismatch privately; keep work on accessible sources moving.
2. Ground the writer portal and the writer's own folder through native metadata/listing. If a search returns no children but current evidence points to a known folder, perform **one bounded direct folder listing** before declaring it empty. Record pagination/completeness; do not turn an empty search, cached title or permission error into “no filing.”
3. Portal and email are independent source paths. An empty or inaccessible portal folder does not block a complete genuine email filing. Search the available path requested by the owner, including relevant overlap since the last successful check.
4. For a requested writer-access fix, read the actual owner/current permissions and verify the writer's account from genuine correspondence or existing approved records. Recommend only the writer's own folder and required role. Workers do not grant access. The controller uses a supported folder-sharing operation under existing authority; do not disguise a folder as a file, broaden general access, reconnect accounts or claim access was granted from a prepared instruction.

## 2. Accept the complete filing

1. Read the complete manuscript through its ending and all substantive attachments. A subject, preview, summary, external path or another agent's claim is not a source acceptance.
2. Preserve the original. Record source identifier, writer, headline, received/modified time, current revision and content hash in the **existing private ledger**. Re-read a changing source before acceptance; retain the accepted snapshot and later update as distinct revisions.
3. Separate filing instructions from publication copy: requested timing, headline/photo placement and attachment credits belong in the work order. Preserve the writer's actual text and full ending.
4. For an inline image, use the parent message's exact attachment metadata and supported download operation. Retrieve the original bytes; a CID marker, filename or body placeholder is not the photograph. Retain filename, credit and provenance. If download is blocked, preserve the text and name only the missing asset; never choose a guessed substitute or label the whole source unreadable.

## 3. Reconcile and route once

1. Read current native Wix drafts and published posts before creation. Match source/revision to the existing canonical story, using exact-title and content/identity evidence as needed. A repeated subject or annual title alone is not a duplicate proof.
2. Additional source copies are aliases. A verified update belongs to its existing canonical story. Preserve the actual native URL, including a provider-added slug suffix; never create another post to recover from an uncertain result.
3. Skip unattended modification of a published item with `hasUnpublishedChanges`; return its current owner/state for reconciliation. Preserve IDs, writer/member, publication dates, access and unrelated edits.
4. Route the complete filing to [GatorBait Editorial](../gatorbait-editorial/SKILL.md) and the existing [newsroom job](../../docs/jobs/newsroom-desk.md). Trusted professional writers receive a quick score/core-stat/opponent/date/byline check and normal copy desk, plus resolution of actual material contradictions. Agent-authored reporting gets full dated claim checks. Preserve substantive voice; do not re-report every observation or make routine publication wait for a transcript of every supplied quote.
5. Keep supported corrections, unresolved meaning/identity conflicts and stylistic exceptions separate. Run the existing house-voice checker on final copy; preserve actual writer bylines and honest photo credits. Never invent missing prose or infer authorship from style.

## 4. Hand off with evidence

Use [the handoff contract](references/handoff-contract.md). Verify that the existing Muse/receiving route is actually reachable before dispatch. A local file, message transport success, named role or configured heartbeat does not establish receipt.

- Record **prepared**, **sent**, **accepted** and **completed** separately. Require acknowledgment of the exact source/revision, next action and checks before marking accepted.
- For post-publication Muse work, include the verified canonical post ID/URL, actual writer, approved permanent art and exact credit. Reconcile the existing article/channel/destination claim and native provider state before a retry.
- Final artwork comes only from **regular ChatGPT Pro, normal Chat mode**. Muse prepares briefs and authentic approved assets; technical workers QA, mechanically export and integrate the approved master. Follow [Graphic Design](../gatorbait-graphic-design/SKILL.md). No replacement creative from another generator.
- Keep publication, independent website QC, Spaces/device proof, email delivery, Muse acceptance and social publication as separate states. Presentation corrections never replay distribution.

## Output and closeout

Return a compact private packet: verified source identity/revision/hash; complete copy and asset references; existing story/draft match; supported corrections and targeted unresolved flags; next owner/action/checks; and honest handoff state. Keep manuscripts, private mail/file identifiers, addresses, attachments and signed URLs out of public git/issues. Public records contain safe operational conclusions only.

Documentation defines behavior, not a running service. Do not claim automated intake or handoff completion without an actual scheduled run and receiving-stage evidence. Do not add another timer or ledger. Resolve routine authorized work; escalate only the specific unresolved source, access, permission or material factual blocker.
