# Source-specific handoff contract

Use the existing private story ledger and receiving route. This format does not create a new queue, agent service or permission.

| Field | Required evidence |
| --- | --- |
| Work item | Existing private claim and assigned scope; one production writer |
| Source | Verified writer, complete text/ending, source identifier, accepted revision/hash and source time |
| Canonical match | Current Wix post/draft ID and actual URL, or documented negative duplicate check |
| Copy desk | Supported edits with their basis; targeted meaning/identity conflicts; house-voice disposition |
| Media | Original available asset, identity/credit and requested placement; explicit missing-asset state if blocked |
| Art brief | Regular ChatGPT Pro normal Chat origin; approved photography/logos; original master and provenance required |
| Next stage | Receiving owner, exact action, success check and rollback when a mutation is authorized |
| Receipt | Prepared/sent/accepted/completed; acknowledgment keyed to the exact item and revision |
| Distribution | Separate publication, website QC, email, push/device and social/provider outcomes |

If the receiver is unreachable, retain **prepared, not accepted** and deliver the usable packet to the controller. Never create a replacement Muse, second publisher, scheduler or social claim registry. After a timeout or uncertain write, read the destination state before any retry.

Relative terms such as “last night” must resolve to a calendar date and timezone in the packet. A previously verified result does not automatically describe the latest game. Keep current facts out of permanent role instructions; use dated evidence in each work item.
